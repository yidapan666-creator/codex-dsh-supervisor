# Changelog

- **Durable reconnect and task-token guard.** Dispatches can carry an idempotency `requestId`; `dsh_runs` rediscovers supervised roots and `dsh_recover` reattaches without prompt replay. Host crash interruption now requires an explicit `parentRunId` continuation. Optional per-task/default token budgets are pinned in task packets and enforced inside the independent Host across persisted run-tree sessions with request preflight, atomic input/output reservations, per-request output caps, and provider-usage settlement. This prevents concurrent allowance oversell while honestly remaining a cutoff rather than an exact provider-billing cap. The user's existing `dsh-usage-monitor` can be queried through its localhost session endpoint as non-authoritative, failure-contained observability; no monitor source was modified.

Notable changes to dsh-gate, tracked from the pre-publication baseline.

## Unreleased

- **Versioned decision operations.** Moved the recommended policy configuration to immutable JSON files, added canonical policy digests and durable per-run active/shadow pins, and made restart recovery resolve the exact pinned catalog entry or fail closed. Added an `explain`/`dry-run` CLI for facts-to-rule diagnostics. Shadow evaluation shares the active engine, records its candidate outcome and behavioral difference, and never controls runtime delivery.
- **Token-free durable run journal.** Added an independent `@dsh-gate/run-journal` package and connected it only to durable terminal observations. One atomic, idempotently addressed JSON record reuses existing objective, handoff, runtime activity, verification, failure, and bounded decision facts with zero extra model calls; transient waits, messages, reasoning, arguments, outputs, stale requests, and temporary Host/protocol failures are excluded. Journal failures fail open. `rag-context` now converts run records into small provenance-carrying lexical chunks without enabling runtime retrieval or context injection.
- **Explainable decision policy and standalone RAG baseline.** Replaced the hard-coded worker-decision interruption with structured category/impact/blocking facts evaluated by a versioned, dependency-free policy; protocol boundaries stay locked, every observation reports the matched action/reason, and only task packets—not workers—can pre-authorize decision categories. Added an intentionally unconnected `@dsh-gate/rag-context` package with retrieval ports, identifier-aware lexical ranking, provenance/filtering, context budgets, RRF, tests, and a source-backed integration roadmap; it performs no model, embedding, network, vector-store, MCP, or DSH integration.
- **Supervision protocol v2.** Durable DSH `sessionId` is now separate from a unique per-execution `runId`; stale waits and controls are rejected, canonical handoff results validate session/run/token identity, and completion still requires both a valid handoff and its corresponding `turn/end`. Task packets carry optional Git baseline, parent run, and pre-authorized child budget fields. The Host now enforces `maxDirectChildren` with persisted creation facts and atomic in-flight reservations instead of relying on prompt compliance.
- **Bounded live supervision.** Added non-concluding `supervisor_progress` with strict fields, identity checks, deduplication, one-minute ordinary rate limiting, and policy-evaluated decision requests. Five-minute heartbeats keep runtime-derived step/tool/token totals, add activity coverage plus event-correlated verification evidence, and never copy reasoning, logs, diffs, arguments, or outputs.
- **Reconnect and writer reliability.** Waits fold mux churn from cache and reconcile authoritatively before visible boundaries instead of refreshing history per event. Session reconnect scans configured Hosts and binds the discovered Host, failures use structured envelopes, interaction answers validate the stable `rpcId`, and writer run leases release at their corresponding `turn/end` without adding a workspace lock manager. Concurrent auto-launch requests now coalesce inside one MCP process, while the recommended `host:start` command uses a short cross-process startup lease so several MCP processes reconnect to one independently lived Host instead of racing duplicate spawns.
- **Authoritative session workspaces.** New sessions require an absolute target-project cwd, validate it as an existing directory, resolve symlinks before Host creation, and report the canonical path. Reconnect keeps the durable session cwd and rejects a different requested path, preventing a worker or DSH Web session from silently landing in the Host or gateway repository.
- **Exact recovery identity.** `dsh_recover` requires the durable `sessionId + runId`; stale or other protocol-failed recovery no longer carries a contradictory `REATTACHED` marker.
- **Explicit Codex skill installation.** Added `pnpm skill:install -- --target <absolute-personal-skills-dir>`; it never guesses a global directory, refuses accidental overwrite, and preserves an existing install as a recoverable timestamped backup when `--force` is requested.
- **Single discoverable Skill install.** The installer accepts pnpm's `--` separator, stores recoverable backups outside the scanned skills directory, and migrates legacy sibling backups so Codex discovers only one active `codex-dsh-supervisor` definition.
- **Clean-checkout CI.** GitHub Actions now runs the pinned public-source bootstrap followed by the complete workspace verification on pull requests and pushes to `main`. The root Vitest configuration includes only this repository's package and script test directories, so the managed upstream checkout under `.dsh-state/` is never rediscovered as part of this project's suite.
- **Real Host loader compatibility.** Kept public rc.8 tool schemas within DSH's supported structural DSL and moved progress/handoff length and collection bounds to the authoritative Host execute boundary. This preserves the same rejection limits while allowing the isolated production profile to boot.
- **Reproducible public-source deployment.** New `scripts/dsh-gate.mjs` workflow: `pnpm bootstrap` fetches the pinned public DSH fork commit (`7212c955438c70c9a2d168f67e85a8014b8d4488`, by SHA — never a branch), installs and builds it, reuses `scripts/link-local-dsh.mjs` for the network-client link, installs `@dsh-gate/supervisor-tools` into an isolated project-local `DSH_HOME` under the gitignored `.dsh-state/`, and never starts the Host; `pnpm run doctor` validates the pin, link, built artifacts, plugin/profile, and optionally a live Host (`protocolVersion=1`, `hostInstanceId`, non-placeholder `version`); `pnpm host:start|status|stop` manage the independent DSH Web Host on `127.0.0.1:8080 --no-open`. `--dry-run`, `--force`, and `--state`/`--dsh-repo`/`--dsh-home`/`--host` overrides are supported; dirty or mismatched checkouts are refused without destructive recovery; failing phases report name, argv, and redacted output. New `DEPLOYMENT.md` documents the contract, update policy, Host independence, browser visibility, clean failure recovery, and the official-upstream-PR limitation. Focused unit tests in `scripts/tests/`.
- **Bounded handoff and overflow convention.** Every model-facing handoff string and collection is capped at the Host execute boundary; MCP independently bounds malformed or legacy durable output and reports affected fields through `handoffTruncated`. When more detail is needed, the worker writes a Markdown report under the gitignored `.dsh-handoff/<runId>/` directory (legacy v1: taskId) inside the session cwd, passes its relative path in `artifacts`, and references it from the concise summary. Overflow fails with an actionable error and is never auto-written.
- **GitHub-readiness pass.** Added the MIT license, canonical `yidapan666-creator/dsh-gate` repository metadata, ignore/export hygiene (`.dsh-handoff/`, `.gitattributes`, `.editorconfig`), and accurate setup, contribution, security, and release-status guidance. npm/package publication remains blocked on the upstream DSH network-client release (the fork pin covers source deployments only).
