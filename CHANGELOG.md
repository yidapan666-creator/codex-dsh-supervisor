# Changelog

Notable changes to dsh-gate, tracked from the pre-publication baseline.

## Unreleased

- **Versioned decision operations.** Moved the recommended policy configuration to immutable JSON files, added canonical policy digests and durable per-run active/shadow pins, and made restart recovery resolve the exact pinned catalog entry or fail closed. Added an `explain`/`dry-run` CLI for facts-to-rule diagnostics. Shadow evaluation shares the active engine, records its candidate outcome and behavioral difference, and never controls runtime delivery.
- **Token-free durable run journal.** Added an independent `@dsh-gate/run-journal` package and connected it only to durable terminal observations. One atomic, idempotently addressed JSON record reuses existing objective, handoff, runtime activity, verification, failure, and bounded decision facts with zero extra model calls; transient waits, messages, reasoning, arguments, outputs, stale requests, and temporary Host/protocol failures are excluded. Journal failures fail open. `rag-context` now converts run records into small provenance-carrying lexical chunks without enabling runtime retrieval or context injection.
- **Explainable decision policy and standalone RAG baseline.** Replaced the hard-coded worker-decision interruption with structured category/impact/blocking facts evaluated by a versioned, dependency-free policy; protocol boundaries stay locked, every observation reports the matched action/reason, and only task packets—not workers—can pre-authorize decision categories. Added an intentionally unconnected `@dsh-gate/rag-context` package with retrieval ports, identifier-aware lexical ranking, provenance/filtering, context budgets, RRF, tests, and a source-backed integration roadmap; it performs no model, embedding, network, vector-store, MCP, or DSH integration.
- **Supervision protocol v2.** Durable DSH `sessionId` is now separate from a unique per-execution `runId`; stale waits and controls are rejected, canonical handoff results validate session/run/token identity, and completion still requires both a valid handoff and its corresponding `turn/end`. Task packets carry optional Git baseline, parent run, and pre-authorized child budget fields.
- **Bounded live supervision.** Added non-concluding `supervisor_progress` with strict fields, identity checks, deduplication, one-minute ordinary rate limiting, and policy-evaluated decision requests. Five-minute heartbeats keep runtime-derived step/tool/token totals, add activity coverage plus event-correlated verification evidence, and never copy reasoning, logs, diffs, arguments, or outputs.
- **Reconnect and writer reliability.** Waits fold mux churn from cache and reconcile authoritatively before visible boundaries instead of refreshing history per event. Session reconnect scans configured Hosts and binds the discovered Host, failures use structured envelopes, interaction answers validate the stable `rpcId`, and writer run leases release at their corresponding `turn/end` without adding a workspace lock manager.
- **Explicit Codex skill installation.** Added `pnpm skill:install -- --target <absolute-personal-skills-dir>`; it never guesses a global directory, refuses accidental overwrite, and preserves an existing install as a recoverable timestamped backup when `--force` is requested.
- **Reproducible public-source deployment.** New `scripts/dsh-gate.mjs` workflow: `pnpm bootstrap` fetches the pinned public DSH fork commit (`7212c955438c70c9a2d168f67e85a8014b8d4488`, by SHA — never a branch), installs and builds it, reuses `scripts/link-local-dsh.mjs` for the network-client link, installs `@dsh-gate/supervisor-tools` into an isolated project-local `DSH_HOME` under the gitignored `.dsh-state/`, and never starts the Host; `pnpm run doctor` validates the pin, link, built artifacts, plugin/profile, and optionally a live Host (`protocolVersion=1`, `hostInstanceId`, non-placeholder `version`); `pnpm host:start|status|stop` manage the independent DSH Web Host on `127.0.0.1:8080 --no-open`. `--dry-run`, `--force`, and `--state`/`--dsh-repo`/`--dsh-home`/`--host` overrides are supported; dirty or mismatched checkouts are refused without destructive recovery; failing phases report name, argv, and redacted output. New `DEPLOYMENT.md` documents the contract, update policy, Host independence, browser visibility, clean failure recovery, and the official-upstream-PR limitation. Focused unit tests in `scripts/tests/`.
- **Long-handoff overflow convention.** `supervisor_handoff.summary` is capped at 2048 characters. When more detail is needed, the worker writes a Markdown report under the gitignored `.dsh-handoff/<runId>/` directory (legacy v1: taskId) inside the session cwd, passes its relative path in `artifacts`, and references it from the concise summary. Over-limit summaries fail with an actionable error and are never auto-written.
- **GitHub-readiness pass.** Added the MIT license, canonical `yidapan666-creator/dsh-gate` repository metadata, ignore/export hygiene (`.dsh-handoff/`, `.gitattributes`, `.editorconfig`), and accurate setup, contribution, security, and release-status guidance. npm/package publication remains blocked on the upstream DSH network-client release (the fork pin covers source deployments only).

## Baseline

- MCP supervision gateway over DeepSeek Harness: `dsh_start_or_connect`, `dsh_task`, `dsh_wait`, `dsh_steer`, `dsh_answer_question`, `dsh_answer_approval`, `dsh_cancel`, `dsh_agents`, `dsh_interrupt_agent`.
- DSH-side supervisor-tools plugin: `supervisor_handoff`, `supervisor_report_failure`, and artifact admission.
- Operator skills (`dsh-supervised-worker`, `codex-dsh-supervisor`), example Codex/DSH configuration, and protocol documentation.
